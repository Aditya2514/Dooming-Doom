Dooming Doom: an agent that remembers what matters

Yugaantar 2026 · DevForge · Track 1 "Can It Play DOOM?" · repository Aditya2514/Dooming-Doom · results as of 26 Nov, 20:00 (preliminary)
USP. A recurrent agent with an inventory-conditioned episodic memory: it stores observations that may matter later (a locked door ahead, a key in view, a new area, plus recent snapshots) and learns, with attention, which of them to retrieve, using its current keys as part of the query. "The locked door I saw a minute ago" can become relevant the moment a key is picked up, with no rule telling it to go back. Everything is trained from scratch with our own recurrent PPO; the agent sees only the official observation.
Acting network: 885,929 parameters (GRU-only baseline: 691,401). Training adds a privileged critic (16 ground-truth inputs incl. ticks remaining) and an auxiliary "damage within 8 steps" head, both absent from the submission.

1 · Sensory representation

We use three official signals and no pixels (rays already summarise geometry; pixels cost most of a training budget):

  • Rays: 64 rays over 360° as 7 channels (distance + one-hot hit type: wall, door, locked door, enemy, item). Conv1d with circular padding, because ray 63 neighbours ray 0.
  • Entities: up to 32 visible objects (type embedding + distance, bearing, relative velocity), masked self-attention and attention pooling with a learned null token, so any number of enemies (including none) is handled.
  • Scalars: 17 vitals (health, ammo, 6 key flags, own velocity) + the 9 buttons pressed last step (USE and weapon switch act on button-down, so the policy must see what it pressed) + an observable reward (keys gained, health lost) + elapsed time.

One shared adapter builds these tensors for both training and DoomAgent; a test proves bit-identical tensors on real games.

2 · Neural architecture

See the figure above. Actions are the official MultiBinary(9): nine independent Bernoulli outputs; the joint log-probability is their sum. Inference costs 4.6 ms per decision on 1 CPU thread (budget 40 ms).

3 · Spatial memory design

There are no coordinates in the observation, so spatial memory has two parts: the GRU (short-range, continuous) and the episodic memory (long-range, explicit).

  • What is written: 8 recent slots (every 8 decisions, ring buffer) and 8 event slots, written when a condition starts: locked door ahead, door ahead, key in view, inventory change, new area (a rotation-invariant change of the ray-distance profile, calibrated on real maps). A reason cannot rewrite within 16 decisions; eviction replaces the oldest record of the most-represented reason. These rules only decide what is remembered, never what to do.
  • How it is read: each record's content is encoded once with the same encoders (cacheable), its age is added at every read, and a query built from the current view, the previous GRU state and the current key flags attends over the 16 records plus a learned null record. The result joins the current features before the GRU.
  • Correctness gates (all pass): no information crosses episodes; cached = fresh encodings; PPO recompute with memory reproduces stored log-probs/values; the memory model warm-started from the baseline reproduces it exactly (memory inputs start at zero).

4 · Training and exploration pipeline

  • Recurrent PPO from scratch: 32-step sequences with stored GRU states, GAE (λ 0.95; γ 0.99 combat, 0.995 otherwise), clip 0.2, KL early stop, reward scaling. The map's tick cap is a termination (the scored attempt is over), only our own cutoffs bootstrap. Correctness ladder before any DOOM training: GAE worked examples, recompute (max error 2e-6), first-minibatch ratio 1, a memory toy task (98% solved).
  • Rewards mirror the scorer, computed only from training-time ground truth: exit (+10 plus health and time bonus), keys (+2), first opening of doors (+0.5) and locked doors (+2.0), new 128-unit cells (+0.02, capped), kills (+0.5), damage, early death, time, and a small ammo cost (our addition). Door rewards went live only after scripted engine tests passed for every door and lock type.
  • Exploration: first-visit cell bonus (no farming: capped, first visit only), door/key progression rewards, entropy bonus, and a curriculum that grows map size and dependency depth.
  • Maps: our own deterministic UDMF generator, with offline checks (exit reachable; key-door maps: exit unreachable without the key, key reachable). Validation and test layouts never appear in training; Freedoom 2 levels are split the same way.

What we measured, including what didn't work

  • Weapon flipping: videos showed the Stage 1 agent cycling fist/pistol/shotgun (35% of decisions pressed weapon-switch, 50% of time on fists). A learned prior on that button (start at p ≈ 0.02) fixed it without a rule.
  • Curriculum forgetting: starting Stage 3 with 20% replay erased the exit skill in 360k decisions (validation exit 0.80 → 0.10). We resumed from the Stage 2 checkpoint with 50% replay and key-door variant A first, and now monitor rooms exits at every gate.
  • What the memory attends to: on a variant B map before key-door training, attention goes to "key seen" records (0.25 each) and the null record (0.27), not yet to the stored locked door (≈0). Stage 3 is where that link has to be learned; ablations (memory off, cleared at key pickup, records from another episode, no inventory in the query) will measure it on one frozen checkpoint.
  • Engineering: a Windows engine-latency fix (3.2× faster), in-engine map switching (8× faster than restarts), single-WAD worker schedules, and a fix for orphaned engine processes; 101 automated tests.
